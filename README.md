# 棚卸アプリ(Firebase版)

JANコード、商品名、予定数を登録し、棚卸数量を入力して差異を確認するWebアプリです。部屋コードまたは共有リンクで、複数端末から同じ棚卸データをリアルタイムに共有できます。

旧版(Supabase版)からの主な変更点:

| 項目 | 旧版 | この版 |
| --- | --- | --- |
| 保存先 | Supabase(無料枠は1週間未使用でプロジェクトが一時停止) | **Firebase Firestore**(無料Sparkプランは自動停止なし) |
| 同期 | 3秒ごとのポーリング | **リアルタイム同期**(変更が即座に全端末へ届く) |
| オフライン | 手動の再送処理 | SDK標準のオフラインキャッシュ・自動再送 |
| スキャン(Safari等) | 旧ZXing(CDN読み込み) | **zxing-wasm同梱**(高速・CDN不要) |
| スキャン精度 | 全画面をデコード | 中央の読取窓だけをデコード + **チェックデジット検証** + 連続フレーム一致で確定 |
| 連続読取 | 1点ごとに「読取」ボタンを押す | **ハンズフリー自動加算**(かざすだけで+1、ビープ音・バイブ付き) |
| 補助機能 | - | ライト(トーチ)・ズーム・直前取消(Undo)・進捗率表示 |

## セットアップ

### 1. Firebaseプロジェクトを作る(無料)

1. [Firebaseコンソール](https://console.firebase.google.com/) で「プロジェクトを追加」を押します(Googleアカウントがあれば無料。クレジットカード不要)。
2. プロジェクト名は任意。Google アナリティクスは「無効」でかまいません。

### 2. Firestoreを有効にする

1. 左メニューの「構築」>「Firestore Database」>「データベースを作成」。
2. ロケーションは `asia-northeast1`(東京)がおすすめ。**本番環境モード**で作成します。
3. 「ルール」タブを開き、このリポジトリの `firestore.rules` の内容を貼り付けて「公開」します。

### 3. Webアプリを登録して設定を貼る

1. プロジェクトの設定(歯車アイコン)>「全般」>「マイアプリ」>「アプリを追加」> Web(`</>`)を選びます。
2. 表示された `firebaseConfig` の値を、このリポジトリの `firebase-config.js` に貼り付けます。

```js
window.INVENTORY_FIREBASE = {
  apiKey: "AIza....",
  authDomain: "your-project.firebaseapp.com",
  projectId: "your-project",
  storageBucket: "your-project.firebasestorage.app",
  messagingSenderId: "000000000000",
  appId: "1:000000000000:web:xxxxxxxxxxxxxxxx"
};
```

`firebase-config.js` を設定するまでは、この端末だけで動くローカルモードになります(カメラ読取などは試せます)。

### 4. (任意・推奨)期限切れデータの自動削除

部屋は作成から7日で期限切れになります。アプリ側でも掃除しますが、Firestoreの **TTLポリシー** を設定するとサーバー側で自動削除されます。

1. Google Cloudコンソールの [Firestore TTL](https://console.cloud.google.com/firestore/databases/-default-/ttl) を開きます。
2. 次の3つのTTLポリシーを作成します(いずれもフィールドは `expiresAt`)。
   - コレクショングループ `rooms`
   - コレクショングループ `products`
   - コレクショングループ `entries`

### 5. GitHub Pagesに置く

1. このリポジトリの中身(`index.html`, `styles.css`, `js/`, `vendor/`, `firebase-config.js`, `.nojekyll`)をリポジトリ直下へ置きます。
2. リポジトリの `Settings` > `Pages` で `Deploy from a branch`、ブランチ `main` / フォルダ `/ root` を選びます。
3. 数分後に `https://ユーザー名.github.io/リポジトリ名/` で開けます。GitHub PagesはHTTPSなので、スマホからでもカメラ読取が使えます。

Cloudflare Pages / Vercel / Firebase Hosting などの静的ホスティングでも同じ構成で動きます。ビルドは不要です。

### 無料枠の目安

Firebase Sparkプラン(無料): Firestore 1GiB保存 / 読み取り5万回・書き込み2万回/日。リアルタイム同期はポーリングと違い変更があったときだけ読み取りが発生するため、数人での棚卸なら無料枠で十分収まります。**Supabaseと違い、使わない期間があってもプロジェクトは停止されません。**

## 使い方

- 最初の端末で担当者名を入力し、「部屋を作る」を押します。
- 表示された部屋コードを伝えるか、「リンクコピー」で共有リンクを送ります。
- 別端末はリンクを開くか、部屋コードを入力し、担当者名を入れて参加します。
- 入力内容はリアルタイムに全端末へ同期されます。電波が切れても端末に保存され、復帰時に自動送信されます。
- 入力画面には、その端末で入力した明細だけが表示されます。
- 未登録商品を入力する場合、数字だけならJANとして、文字を含む場合は商品名として仮登録します。
- 棚番は数字だけなら3桁にゼロ埋めし、英字や記号を含む棚番も20文字まで入力できます。
- 確認画面では全端末の入力が合計され、商品ごとに棚番と担当者別の内訳、進捗率(入力済みSKU / 全SKU)が表示されます。
- 確認画面ではJAN / 商品名 / 担当者検索と「差異ありだけ表示」で確認表を絞り込めます。差異確認は差異の絶対値が大きい順に並びます。
- 部屋に入った直後は設定画面がロックされています。商品マスタを変更するときだけ「ロック解除」を押し、確認欄に `解除` と入力してください。
- 部屋は作成から7日経過すると削除されます。

## カメラ読取

### 対応エンジン

- Chrome / Edge / Android: ブラウザ標準の `BarcodeDetector`(ハードウェア支援あり、最速)
- iOS Safari など未対応ブラウザ: 同梱の [zxing-wasm](https://github.com/Sec-ant/zxing-wasm)(WebAssembly版ZXing。CDN不要でオフラインでも読み込めます)

対応コード: JAN/EAN-13, EAN-8, UPC-A, UPC-E, CODE128, ITF, CODE39, QRコード

### 精度・速度を上げる仕組み(有料棚卸アプリを参考)

- **読取窓(ROI)**: 画面中央の枠内だけをデコードします。処理が速くなり、隣のバーコードの誤読も防ぎます。
- **チェックデジット検証**: JAN/EAN/UPCは読み取った数字のチェックデジットを再計算し、合わないコードは捨てます。
- **連続フレーム一致**: 同じコードを連続フレームで確認してから確定します(1回の誤読では登録されません)。
- **クールダウン**: 同じ商品は約1.5秒間は再加算されません(二重登録防止)。連続で数えたい場合は1.5秒あけてかざし直してください。
- **フィードバック**: 読取成功でビープ音+バイブ+画面フラッシュ。
- **ライト / ズーム**: 対応端末では暗所用のライト点灯とズームがスキャン画面から操作できます。

### 読取モード

- **カメラ読取(単発)**: 1点だけ読み取って入力欄へ。棚番が入っていればそのまま加算まで行います。
- **連続スキャン(自動加算)**: 棚番を決めて商品を順にかざすだけで1点ずつ加算されます。読み間違えたら「直前取消」ですぐ戻せます。

## CSV取込

CSVの列名は次に対応しています。

- `jan` または `barcode`, `code`, `sku`, `商品コード`, `JANコード`, `バーコード`, `品番`, `品目コード`, `管理コード`
- `name` または `product`, `item`, `description`, `商品名`, `商品名称`, `品名`, `品目名`, `品目`, `名称`, `商品`, `明細名`
- `expected` または `stock`, `qty`, `quantity`, `予定数`, `理論在庫`, `在庫数`, `個数`, `数量`, `数`, `在庫`, `現在庫`, `総数`

関係ない列が混ざっていても無視します。既存商品はCSVにある列だけ更新でき、予定数列が無い場合は既存の予定数を残します。在庫数は `100点` や `1,000` のような表記も数値として読み取り、金額・価格・原価・販売価格などの列は予定数として扱いません。JANだけの行は商品名にJANを仮設定し、商品名だけの行は `NOJAN-...` の仮コードで取り込みます。

JAN未入力で商品名だけ仮登録したあと、同じ商品名にJANが入ったデータを取り込むと同一商品として統合します。列名が合わない場合やヘッダーが無い場合も、8桁・12桁・13桁・14桁などの商品コードらしい数字列を判断材料にして取り込みます。`商品ID / 商品コード / 商品名` のように1つのセル内へコードと商品名がまとまっているCSVも分けて読み取ります。

## CSV出力

CSV出力は確認画面の差異表とは別の出力用表を使います。列は左から `商品コード`, `棚卸数量`, `明細メモ` です。商品コードにはJAN、棚卸数量にはJANごとの入力合計、明細メモには担当名を含めない棚番別の数量内訳を出力します。出力用表とCSVは商品コードの小さい順に並びます。

## データ構造

同時入力に強くするため、1回の入力ごとに1ドキュメントで保存します。複数人が同時に入力しても上書き衝突が起きません。

```
rooms/{部屋コード}                     … createdAt, expiresAt
rooms/{部屋コード}/products/{JAN}      … jan, name, expected, updatedAt, expiresAt
rooms/{部屋コード}/entries/{入力ID}    … deviceId, userName, jan, shelfNo, qty, createdAt, updatedAt, expiresAt
```

## ローカルで試す

ビルド不要の静的サイトです。リポジトリのフォルダで次のように起動できます。

```
python3 -m http.server 4175
```

`http://127.0.0.1:4175` をブラウザで開きます。`localhost` / `127.0.0.1` は安全な環境として扱われるため、カメラ読取も使えます。
